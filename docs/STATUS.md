## Перенос на Django

16 ноября 2026 года согласован [план из пяти этапов](DJANGO-PLAN.md). Для новой версии создана ветка `codex/oldschool-journal-django`. В ней проект Django находится в `django_blog/`. Команды запуска в Windows описаны в [README](../README.md#локальный-запуск-django-на-windows).

Этап 1 выполнен. В окружении `.venv` установлен Django 5.2.19 под Python 3.12.10. Команды `manage.py check` и `manage.py migrate --check` прошли. Таблицы SQLite созданы. Локальный сервер вернул успешный ответ, и в Chrome открылась страница «OldSchool Journal».

Этап 2 выполнен. Добавлены главная, статьи и города, включая страницы отдельных записей. Изменение структуры базы применено. Шесть автотестов прошли, страницы проверены в Chrome на Windows с пробной статьёй и городом во временной базе. Для Mac подготовлены [команды запуска](../README.md#локальный-запуск-django-на-mac). На Mac запуск ещё предстоит проверить.

Этап 3 выполнен. Читатель регистрируется и входит по электронной почте. Администратор управляет статьями и городами через панель Django. Миграции применены. 14 автотестов прошли. В Chrome проверены отображение форм регистрации и входа и перенаправление гостя с `/admin/` на страницу входа. Полные сценарии отправки форм и изменения записей проверены автотестами.

Этап 4 выполнен. Перенесены погода и адреса для чтения статей, городов, комментариев и погоды. В Chrome проверен демонстрационный режим для Кызылорды. 21 автотест прошёл. Ответ OpenWeather проверен с подставными данными, запрос с действующим ключом ещё предстоит проверить. Этап 5 ожидает подтверждения владельца.

## Что проверено для Rails

На Windows установлен Ruby 3.3.12, проверен синтаксис изменённых файлов Ruby. Политика управления приложениями Windows заблокировала загрузку модуля Ruby с ошибкой `4551`. Из-за этого установка библиотек и запуск сервера не завершились. Автотесты и проверка в браузере остаются открытыми.

По последней проверке WSL установлен, Ubuntu ещё предстоит настроить. Команды проверки, пути установки и история обсуждения собраны в [журнале WSL](WSL.md).

При чтении кода также видна ошибка в обработчике `GET /api/v1/articles/:id`. Он загружает запись в переменную `article`, а затем обращается к `articles`. В списке статей для ответа указано поле `body`, хотя в таблице статей хранится `content`. Эти места стоит проверить после запуска.

## Как возобновить запуск Rails

1. Установить Ubuntu командой `wsl --install -d Ubuntu` из PowerShell от имени администратора. Затем открыть Ubuntu и завершить первоначальную настройку. В Ubuntu подготовить рабочую среду Ruby. [Инструкция Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install)
2. Установить библиотеки и подготовить локальную базу по [README](../README.md#локальный-запуск-rails).
3. Пройти [проверки маршрутов, входа и прав](TESTING.md). После этого проверить чтение статей по адресам `/api/v1/articles` и `/api/v1/articles/:id`.
