# Журнал обсуждения WSL и запуска OldSchool Journal

## 1. Зачем появилась WSL

При восстановлении блога в Windows установили Ruby 3.3.12 и инструменты сборки RubyInstaller. Ruby показывал свою версию, но Windows заблокировала загрузку модуля `utf_16le.so`. Модуль нужен Ruby для работы с одной из кодировок текста. Windows вернула ошибку `4551`. Запись в журнале подтвердила ограничение политики управления приложениями. Поэтому установка библиотек Rails, локальный запуск сайта и автотесты остались незавершёнными.

WSL расшифровывается как *Windows Subsystem for Linux*, подсистема Windows для Linux. Она позволяет запускать программы Linux на компьютере с Windows. WSL 2 запускает ядро Linux, то есть основную часть системы, в управляемой виртуальной машине. Ubuntu — отдельная среда Linux, которую можно установить внутри WSL. Для блога её предложили как место для запуска Linux-версии Ruby. [Описание WSL от Microsoft](https://learn.microsoft.com/ru-ru/windows/wsl/about)

## 2. Установка и перезагрузка

15 ноября 2026 года команда установки из Codex завершилась ошибкой. Владелец проекта запустил `wsl --install` в PowerShell от имени администратора. На присланном снимке установка WSL 3.0.5 ещё выполнялась. После перезагрузки проверка показала следующее.

| Команда | Результат |
| --- | --- |
| `wsl --version` | Установлена WSL 3.0.5.0. |
| `wsl --status` | WSL 2 выбран по умолчанию. |
| `wsl --list --verbose` | Список установленных дистрибутивов Linux пуст. Ubuntu ещё предстоит установить. |

Получение статуса из обычного процесса Codex вернуло `Wsl/E_ACCESSDENIED`. Повторная проверка с доступом вне ограничений Codex подтвердила результаты в таблице. После перезагрузки по просьбе владельца подготовили карту папок, а работу над кодом и запуск сайта отложили. [Карта проекта](ARCHITECTURE.md)

## 3. Где находятся файлы

| Что | Путь |
| --- | --- |
| Установленные файлы WSL | `C:\Program Files\WSL` |
| Рабочая копия блога | `C:\Users\uolri\OneDrive\Документы\ChatGPT\Сайт Руби блог\blog` |
| Ruby для Windows, установленный для проверки | `C:\Users\uolri\OneDrive\Документы\ChatGPT\Сайт Руби блог\.ruby-runtime\ruby` |
| Возможный путь для Ubuntu | `C:\WSL\Ubuntu`. Путь предложен для будущей установки. |

При установке Ubuntu параметр `--location` задаёт папку для её файлов. Можно выбрать папку на нужном диске. При проверке был виден только локальный диск `C:`, поэтому `C:\WSL\Ubuntu` была бы отдельной папкой на том же диске. Данные Ubuntu в WSL 2 хранятся в файле виртуального диска `ext4.vhdx`, который растёт по мере использования. [Параметры установки](https://learn.microsoft.com/ru-ru/windows/wsl/basic-commands#install) · [Как растёт диск WSL](https://learn.microsoft.com/ru-ru/windows/wsl/disk-space)

## 4. Место на диске и оперативная память

На момент измерения на диске `C:` было свободно около **203 ГБ**. Файлы WSL занимали примерно **1,1 ГБ**, Ruby с инструментами для Windows — **около 1 ГБ**, а блог вместе с историей Git — **меньше 1 МБ**. Для Ubuntu, Ruby для Linux и библиотек Rails обсуждали оценку **3–6 ГБ дополнительно**. Если оставить все установленные компоненты, получится **примерно 5–8 ГБ** суммарно. Размер зависит от выбранных библиотек, обновлений и файлов базы.

На компьютере **32 ГБ оперативной памяти**. Для запущенной Ubuntu и одного локального сервера Rails предварительная оценка — **1–2 ГБ** в обычной работе. Это оценка из обсуждения, фактический расход сайта в Ubuntu ещё предстоит измерить. При сборке библиотек расход может вырасти. Настройки `.wslconfig` при проверке не было, поэтому ориентир для стандартного верхнего предела WSL 2 — примерно **16 ГБ**. Память выделяется по мере работы. Команда `wsl --shutdown` завершает все запущенные среды WSL и освобождает их память. Вместе с Ubuntu остановится работающий в ней локальный сайт. [Настройки памяти](https://learn.microsoft.com/ru-ru/windows/wsl/wsl-config) · [Команда остановки WSL](https://learn.microsoft.com/ru-ru/windows/wsl/basic-commands#shutdown)

## 5. Когда WSL можно убрать

Если блог работает на хостинге, Ruby или Python запускается на сервере хостинга. Владелец открывает сайт из браузера. Для этого WSL на его компьютере не требуется. Для запуска текущего Rails-кода на своём ПК нужна рабочая среда Ruby. С учётом блокировки модуля Ruby в Windows для этого варианта предложена Ubuntu.

Перед удалением Ubuntu потребуется сохранить базу и другие нужные файлы, если они были созданы внутри неё. Удаление дистрибутива WSL удаляет его данные. Рабочая копия блога сейчас находится в указанной выше папке Windows. [Экспорт и удаление дистрибутива](https://learn.microsoft.com/ru-ru/windows/wsl/basic-commands)

## 6. Можно ли сделать тот же блог на Python

Да. Для этого подходит Django, веб-фреймворк для Python. Он предоставляет вход, права доступа и админ-панель. Публичную регистрацию, страницы статей и городов, погоду и проверки нужно перенести или реализовать в новой версии. Существующие стили, изображения, тексты и часть разметки можно использовать повторно. Файлы Ruby и выражения внутри шаблонов Rails нужно заменить кодом Python и шаблонами Django. Если найдётся старая база, перенос записей и учётных записей потребует отдельной проверки. [Возможности Django](https://docs.djangoproject.com/en/5.2/intro/tutorial02/)

Django можно запускать непосредственно в Windows. На этом компьютере проверены Python 3.12.10 и модуль SQLite 3.49.1. SQLite хранит данные в файле и подходит для простой локальной версии. Для такого запуска WSL не требуется. [Установка Django в Windows](https://docs.djangoproject.com/en/5.2/howto/windows/)

| Цель | Подход |
| --- | --- |
| Быстрее продолжить восстановленный сайт и сохранить уже написанную логику | Ruby on Rails. Для этого ПК сначала подготовить Ubuntu или другую рабочую среду Ruby. |
| Учить Python на своём проекте и запускать его прямо в Windows | Python и Django. Восстановленный Rails-блог можно использовать как образец и сохранить в его ветке Git. |

Владелец выбрал Python и Django для локального запуска в Windows. Текущие этапы переноса описаны в [плане](DJANGO-PLAN.md).
