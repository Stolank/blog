# Как устроен OldSchool Journal

Ruby — язык, на котором написана серверная часть блога. Ruby on Rails — набор инструментов, который связывает адреса страниц, обработку запросов и базу данных. В `Gemfile.lock` зафиксированы Rails 8.0.2.1 и Bundler 2.7.1. Bundler устанавливает версии библиотек, записанные для проекта.

## Как открывается список статей

1. Браузер запрашивает адрес `/articles`. В [маршрутах](../config/routes.rb) Rails связывает этот адрес с действием `index` контроллера `ArticlesController`.
2. [Контроллер статей](../app/controllers/articles_controller.rb) обрабатывает запрос. В действии `index` он обращается к модели `Article`.
3. [Модель статьи](../app/models/article.rb) описывает правила для записей в базе. Например, у статьи обязательны заголовок `title` и текст `content`.
4. [Шаблон списка](../app/views/articles/index.html.erb) получает записи от контроллера и превращает их в страницу для браузера. Общая шапка, меню и нижняя часть страницы находятся в [общем шаблоне](../app/views/layouts/application.html.erb).

## Кто что может делать

Гость и вошедший читатель могут открывать списки и отдельные страницы статей и городов. Для создания, редактирования и удаления записей нужна роль `admin`. Панель `/admin/dashboard` тоже проверяет эту роль. Права проверяет сервер через метод `require_admin` в [общем контроллере](../app/controllers/application_controller.rb).

Devise — библиотека Ruby для регистрации и входа. Страница входа находится по адресу `/users/sign_in`, а регистрация — по `/users/sign_up`. Старый адрес `/login` ведёт на форму Devise. Новому пользователю назначается роль `user`, то есть читатель.

## Погода и ответы для программ

Страница `/weather` передаёт название города в [WeatherService](../app/services/weather_service.rb). Для реального запроса к OpenWeather сервис читает `OPENWEATHER_KEY` из переменных окружения. Это настройки, которые терминал передаёт запущенному серверу. Без ключа страница использует демонстрационные данные.

Адреса под `/api/v1/` объявлены для статей, городов, дерева комментариев и погоды. API — интерфейс, через который другая программа запрашивает данные. Здесь ответы формируются в JSON, текстовом формате для структурированных данных. Объявленный маршрут показывает, куда передаётся запрос. Работоспособность проверяется отдельно. Состояние этих проверок указано в [STATUS.md](STATUS.md).
