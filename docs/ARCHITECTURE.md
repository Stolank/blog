# Как устроен OldSchool Journal

## Версия на Django

В папке `django_blog/entries/` находятся модели статей и городов, адреса страниц и тесты. Модель описывает столбцы таблицы. Файлы `entries/migrations/` описывают изменения структуры таблиц, которые команда `manage.py migrate` применяет к локальной базе. Шаблоны страниц лежат в `django_blog/templates/`, общие стили — в `django_blog/static/journal.css`.

Например, запрос к `/articles/` попадает в описанный в `entries/urls.py` список статей. Django получает записи `Article` из SQLite и выводит их через шаблон `templates/entries/article_list.html`. На `/articles/1/` Django ищет одну запись по номеру `1` и, если она есть, показывает полный текст. Города работают по той же схеме.

Форма регистрации находится в `django_blog/journal/accounts.py`. Она использует встроенную таблицу пользователей Django. При регистрации адрес почты становится именем для входа. Django проверяет пароль и хранит его в виде хеша, то есть результата необратимого преобразования. За вход, выход и проверку прав отвечает встроенная система Django. `django_blog/entries/admin.py` добавляет статьи и города в панель `/admin/`.

## Восстановленная версия на Rails

Ruby — язык, на котором написана серверная часть блога. Ruby on Rails — набор инструментов, который связывает адреса страниц, обработку запросов и базу данных. В `Gemfile.lock` зафиксированы Rails 8.0.2.1 и Bundler 2.7.1. Bundler устанавливает версии библиотек, записанные для проекта.

## Карта папок

`blog/` — корень репозитория. Из этой папки выполняются команды Rails и Git. Ниже перечислены папки, которые нужны для первых доработок и проверок.

```text
blog/
├── app/                         Код сайта
│   ├── controllers/             Обработка запросов от браузера и других программ
│   │   ├── admin/                Панель администратора
│   │   └── api/v1/               Первая версия интерфейса для других программ
│   ├── models/                  Записи и правила для данных в базе
│   ├── views/                   Шаблоны страниц и форм
│   │   ├── pages/                Главная страница
│   │   ├── articles/             Список, страница и формы статей
│   │   ├── cities/               Список, страница и формы городов
│   │   ├── weather/              Страница погоды
│   │   ├── admin/dashboard/      Страница администратора
│   │   └── layouts/              Общая шапка, меню и нижняя часть страниц
│   ├── assets/stylesheets/      Оформление страниц
│   ├── javascript/              Код, который выполняется в браузере
│   └── services/                Получение данных от внешних сервисов, сейчас погоды
├── config/                      Маршруты, настройки базы и окружений Rails
├── db/                          Описание базы и история изменений таблиц
│   └── migrate/                 Изменения таблиц по порядку
├── storage/                     Место для локальных файлов базы SQLite
├── bin/                         Команды проекта, включая bin/rails
├── public/                      Готовые файлы, например страницы ошибок
├── test/                        Тесты Rails и пробные записи для тестов
├── spec/                        Дополнительные тесты на RSpec
├── docs/                        Документация проекта
└── notes/                       Заметки из восстановленной ветки
```

В корне также находятся `Gemfile` со списком библиотек и `Gemfile.lock` с точными версиями. В `db/` лежит описание таблиц. Сами записи локального сайта хранятся в `storage/development.sqlite3`, когда эта база создана.

## Как открывается список статей

1. Браузер запрашивает адрес `/articles`. В [маршрутах](../config/routes.rb) Rails связывает этот адрес с действием `index` контроллера `ArticlesController`.
2. [Контроллер статей](../app/controllers/articles_controller.rb) обрабатывает запрос. В действии `index` он обращается к модели `Article`.
3. [Модель статьи](../app/models/article.rb) описывает правила для записей в базе. Например, у статьи обязательны заголовок `title` и текст `content`.
4. [Шаблон списка](../app/views/articles/index.html.erb) получает записи от контроллера и превращает их в страницу для браузера. Общая шапка, меню и нижняя часть страницы находятся в [общем шаблоне](../app/views/layouts/application.html.erb).

## Кто что может делать

Гость и вошедший читатель могут открывать списки и отдельные страницы статей и городов. Для создания, редактирования и удаления записей нужна роль `admin`. Панель `/admin/dashboard` тоже проверяет эту роль. Права проверяет сервер через метод `require_admin` в [общем контроллере](../app/controllers/application_controller.rb).

Devise — библиотека Ruby для регистрации и входа. Страница входа находится по адресу `/users/sign_in`, а регистрация — по `/users/sign_up`. Старый адрес `/login` ведёт на форму Devise. Новому пользователю назначается роль `user`, то есть читатель.

В рабочей копии формы входа и регистрации предоставляет сама библиотека Devise. Её настройки находятся в [`config/initializers/devise.rb`](../config/initializers/devise.rb), а модель пользователя — в [`app/models/user.rb`](../app/models/user.rb).

## Погода и ответы для программ

Страница `/weather` передаёт название города в [WeatherService](../app/services/weather_service.rb). Для реального запроса к OpenWeather сервис читает `OPENWEATHER_KEY` из переменных окружения. Это настройки, которые терминал передаёт запущенному серверу. Без ключа страница использует демонстрационные данные.

Адреса под `/api/v1/` объявлены для статей, городов, дерева комментариев и погоды. API — интерфейс, через который другая программа запрашивает данные. Здесь ответы формируются в JSON, текстовом формате для структурированных данных. Объявленный маршрут показывает, куда передаётся запрос. Работоспособность проверяется отдельно. Состояние этих проверок указано в [STATUS.md](STATUS.md).
