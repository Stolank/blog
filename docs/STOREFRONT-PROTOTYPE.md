# Этап 1. Прототип витрины OldSchool Journal

[План развития](SITE-ROADMAP.md) предлагается реализовать поэтапно. Для первого релиза рекомендуется журнал с каталогом, а оплату стоит включать после выбора рынка и согласования правил заказов. Прототип показывает весь сценарий покупки, чтобы заранее проверить дизайн. Это локальный макет. Цены, остатки, товары и тариф доставки вымышленные. Поля оформления обрабатываются в браузере и никуда не отправляются.

## Как открыть

Откройте [`prototype/storefront/index.html`](../prototype/storefront/index.html) в браузере. Файлы фотографий, оформление и сценарии лежат рядом. Для предпросмотра через локальный сервер выполните команду из папки `blog`. На Windows используйте `python`, на Mac — `python3.12`.

```text
python -m http.server 8012 --bind 127.0.0.1 --directory prototype/storefront
```

Откройте [http://127.0.0.1:8012](http://127.0.0.1:8012). Для демонстрации сервер Django и база данных не нужны.

## Карта страниц и сценарии

| Экран | Что можно проверить |
| --- | --- |
| Главная | Название OldSchool Journal, большая фотография коллекции, переход в каталог и к товарам. |
| Каталог | Отбор керамики, бумаги и света, цена на карточке, отметка об отсутствии товара. |
| Карточка | Фото, название, цена, выбор варианта, наличие и добавление в корзину. |
| Корзина | Количество, ограничение по остатку, удаление товара, пустое состояние и сумма. |
| Оформление | Самовывоз или курьер, обязательный адрес для курьера, пересчёт полной суммы, подтверждение демозаказа. |

После внедрения у журнала сохранятся статьи, города и погода. В общую навигацию добавятся «Журнал» и «Каталог», а ссылки из статей смогут вести на связанные товары. Экраны корзины и оформления будут включены, когда решение о продажах подтверждено.

## Стиль и фотографии

Предложение для утверждения — тёплый светлый фон, тёмно-зелёные действия, заголовки с засечками и предметные фотографии. Палитра и компоненты заданы в `prototype/storefront/storefront.css`. Шапка, кнопки и карточки работают с клавиатуры, а на узком экране блоки выстраиваются в одну колонку там, где это нужно для чтения и оформления.

Встроенный ImageGen создал четыре фотографии в [папке `assets`](../prototype/storefront/assets/). Для главной запросили оливковую кружку, льняной блокнот и настольную лампу в тёплом утреннем свете. Для каталога запросили отдельный квадратный снимок каждого предмета на светлом фоне без надписей и логотипов. Это изображения для проверки направления дизайна.

## Схема данных для следующего этапа

| Запись | Связи и важные правила |
| --- | --- |
| Категория, товар, фотография | Категория содержит товары. У товара может быть несколько фотографий и вариантов. |
| Вариант товара | Хранит уникальный артикул, цену, валюту и остаток. Корзина указывает на конкретный вариант. |
| Заказ и позиция заказа | У заказа несколько позиций. В позиции сохраняются название, артикул и цена на момент покупки. Получение заказа и оплата имеют отдельные статусы. |
| Резерв товара | Привязан к варианту и заказу. У резерва есть срок. Создание резерва и изменение доступного остатка проверяются внутри одной транзакции базы. |
| Платёж и событие провайдера | Платёж связан с заказом. У события провайдера уникальный идентификатор, чтобы повторное уведомление не повторило операцию. |

В прототипе корзина хранит только выбранные товары и количества в текущей сессии вкладки. В рабочем магазине сервер будет заново рассчитывать сумму и проверять остаток. Состояние заказов и оплаты будет храниться в PostgreSQL. Подробности защиты и приёмки этапов находятся в [плане развития](SITE-ROADMAP.md).

## Что нужно утвердить

Дизайн и состав первого выпуска. Для демонстрации использованы предметы для рабочего стола, цены в тенге, самовывоз и пробный тариф курьера. Для рабочего магазина ещё нужно выбрать реальные товары, рынок, условия доставки и решение о включении оплаты в первый релиз.

## Что проверено

В браузере Codex открыт путь от каталога до подтверждения демозаказа. Проверены фильтр по категории, запрет добавления товара без остатка, выбор варианта, ограничение количества, пересчёт доставки и обязательный адрес для курьера. После подтверждения корзина пустая. Главная проверена при ширине окна 390 и 1280 пикселей. На обеих ширинах горизонтальной прокрутки нет.
