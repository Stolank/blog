# OldSchool Journal

Учебный блог OldSchool Journal переносится с Ruby on Rails на Python и Django. Код Django находится в `django_blog/`. Гости могут читать статьи и страницы городов. На сайте есть регистрация и вход. Администратор управляет записями через панель Django. Очерёдность работ описана в [плане](docs/DJANGO-PLAN.md).

## Локальный запуск Django на Windows

Откройте PowerShell в папке репозитория `blog`. Для первого запуска выполните команды по порядку. `venv` создаёт отдельное окружение для библиотек этого проекта. `migrate` создаёт нужные таблицы в локальном файле базы SQLite.

```powershell
python -m venv .venv
cd django_blog
..\.venv\Scripts\python.exe -m pip install -r requirements.txt
..\.venv\Scripts\python.exe manage.py migrate
..\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Для повторного запуска достаточно открыть `blog/django_blog` и выполнить последнюю команду. Сервер останавливается сочетанием `Ctrl+C`. Файл локальной базы `django_blog/db.sqlite3` создаётся автоматически и хранится вне Git.

## Локальный запуск Django на Mac

Для первого запуска нужен Python 3.12. Проверьте его командой `python3.12 --version`. Если репозитория на Mac ещё нет, выполните в Терминале из папки для проектов:

```sh
git clone --branch codex/oldschool-journal-django https://github.com/Stolank/blog.git
cd blog
python3.12 -m venv .venv
cd django_blog
../.venv/bin/python -m pip install -r requirements.txt
../.venv/bin/python manage.py migrate
../.venv/bin/python manage.py runserver 127.0.0.1:8000
```

Если репозиторий уже скачан и нужная ветка открыта, начните с создания `.venv` из корня `blog`. Для повторного запуска из `blog/django_blog` достаточно последней команды. Адрес в браузере тот же — [http://127.0.0.1:8000](http://127.0.0.1:8000).

## Работа над одним проектом на двух компьютерах

На обеих машинах работайте в ветке `codex/oldschool-journal-django`. Перед началом работы при чистом `git status` выполните из `blog` команду `git pull --ff-only`, чтобы получить отправленные изменения без создания коммита слияния. После своих изменений сохраните их коммитом и отправьте на GitHub командой `git push origin codex/oldschool-journal-django`, когда они готовы к отправке. Тогда второй компьютер сможет их получить.

На каждой машине свои `.venv` и `django_blog/db.sqlite3`. Git переносит код и файлы изменений структуры базы. После получения новой версии запустите `manage.py migrate` командой для своей системы. Локальные статьи и города из файла базы автоматически на второй компьютер не переносятся. В новой базе списки пустые.

## Вход и управление записями

Чтобы создать читателя, откройте «Регистрация», введите электронную почту и пароль, затем войдите через меню. Читать статьи и города можно и без учётной записи. Для управления записями создайте локального администратора из папки `blog/django_blog` после команды `migrate`.

```powershell
# Windows
..\.venv\Scripts\python.exe manage.py createsuperuser
```

```sh
# Mac
../.venv/bin/python manage.py createsuperuser
```

Команда попросит придумать имя пользователя и пароль. Войдите с ними через «Войти» и откройте «Управление». В панели можно добавлять, редактировать и удалять статьи и города. Учётные записи хранятся в локальной базе, поэтому для новой базы на втором компьютере администратора нужно создать отдельно.

## Погода и чтение данных

Откройте «Погода» в меню. Без ключа OpenWeather страница и ответ для программ показывают явно помеченные демонстрационные данные. Для реальных измерений перед запуском Django задайте `OPENWEATHER_KEY` в том же терминале. Подставьте свой ключ вместо `ВАШ_КЛЮЧ` и храните его вне Git.

```powershell
# Windows
$env:OPENWEATHER_KEY = 'ВАШ_КЛЮЧ'
```

```sh
# Mac
export OPENWEATHER_KEY='ВАШ_КЛЮЧ'
```

Статьи, города, комментарии и погода доступны для чтения через API, то есть адреса, откуда другая программа может получить данные. Адреса и формат ответов описаны в [архитектуре Django](docs/ARCHITECTURE.md#адреса-для-чтения-данных).

## Локальный запуск Rails

Откройте терминал в папке `blog`. Установите Ruby 3.3 и Bundler 2.7.1.
В Windows используйте [RubyInstaller с Devkit](https://rubyinstaller.org/downloads/).
Devkit содержит инструменты, которые нужны для сборки некоторых библиотек Ruby.

```text
gem install bundler -v 2.7.1
```

В Windows добавьте поддержку вашей платформы в список версий библиотек:

```text
bundle _2.7.1_ lock --add-platform x64-mingw-ucrt
```

Установите библиотеки, подготовьте локальную базу данных и запустите сайт:

```text
bundle _2.7.1_ install
bundle _2.7.1_ exec ruby bin/rails db:prepare
bundle _2.7.1_ exec ruby bin/rails server -b 127.0.0.1
```

Когда сервер запустится, откройте [http://127.0.0.1:3000](http://127.0.0.1:3000).
Остановить сервер можно сочетанием `Ctrl+C` в терминале.

Данные локального сайта хранятся в `storage/development.sqlite3`. При первом
запуске создаётся новая база. В Git сохранён код проекта и описание структуры
базы. Для возврата старых записей нужен прежний файл базы или его резервная копия.
