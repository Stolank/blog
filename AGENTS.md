# Инструкции для работы с OldSchool Journal

- Перед каждой новой задачей по OldSchool Journal прочитайте все файлы `.md` проекта. Начните с этого файла и `README.md`, затем прочитайте документацию в `docs/` и другие Markdown-файлы, которые есть в репозитории на момент работы. [Журнал WSL](docs/WSL.md) содержит историю настройки, пути и варианты запуска.
- Репозиторий блога находится в папке `blog`. Команды Git выполняйте из неё, а команды Django — из `blog/django_blog` согласно инструкциям для [Windows](README.md#локальный-запуск-django-на-windows) и [Mac](README.md#локальный-запуск-django-на-mac).
- Перед изменениями проверьте текущую ветку и рабочие файлы командой `git status -sb`. История восстановления и незавершённые проверки описаны в [состоянии проекта](docs/STATUS.md).
- Выполняйте [план переноса на Django](docs/DJANGO-PLAN.md) по этапам. Сохраняйте критические изменения отдельными коммитами, сообщайте результат и переходите к следующему этапу после подтверждения владельца.
- При переносе используйте файлы Rails как образец. Изменения версии Python вносите в `django_blog/`. При изменении структуры базы добавляйте миграцию, то есть отдельный файл с описанием изменения таблиц.
- Для локальной работы Django использует `django_blog/db.sqlite3`. При изменении входа или прав проверяйте доступ гостя, читателя и администратора.
- Ключи сервисов передавайте через переменные окружения. Файлы базы данных, ключи, журналы и установленные библиотеки держите вне Git.
- Команды запуска находятся в [README](README.md). Порядок проверки описан в [руководстве по тестированию](docs/TESTING.md). В отчёте различайте проверку синтаксиса, запуск автотестов и проверку в браузере. Указывайте, если какой-то шаг был недоступен.
- В пояснениях для владельца проекта используйте русский язык. При первом упоминании поясняйте специальный термин простыми словами.
